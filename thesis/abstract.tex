\chapter*{Sommario}
\addcontentsline{toc}{chapter}{Sommario}

eBPF (extended Berkeley Packet Filter) è diventato un componente fondamentale
dei moderni sistemi Linux, consentendo l'esecuzione sicura e sandboxed di programmi
utente all'interno del kernel per applicazioni di rete, osservabilità e sicurezza.
Il verifier eBPF~--- il componente del kernel responsabile della garanzia di
sicurezza dei programmi~--- rappresenta pertanto un obiettivo di alto valore:
falle logiche nel verifier possono permettere a codice non privilegiato di uscire
dalla sandbox e compromettere il sistema host.

Questa tesi indaga se un large language model (LLM) fine-tunato possa effettuare il
fuzzing del verifier eBPF di Linux --- una direzione per la quale non abbiamo
trovato lavori pubblicati precedenti. A partire da circa 2 milioni di programmi
eBPF raccolti al confine FFI del kernel mediante una versione modificata del fuzzer
Buzzer, curiamo un dataset bilanciato di 27\,000 campioni distribuiti tra le classi
di errore del verifier ed eseguiamo il fine-tuning di Qwen2.5-Coder-1.5B tramite
QLoRA. Applichiamo poi l'apprendimento per rinforzo GRPO con un reward derivato
dalla copertura del codice kernel (KCOV), usando un reward vincolato alla validità
con soglia morbida che mantiene non nulla la varianza del reward intra-gruppo
--- correggendo il collasso del gradiente per starvation --- premiando comunque
solo i programmi validi.

Il risultato centrale è che \emph{la diversità, non la validità, è il muro}.
Il fine-tuning porta il modello a generare programmi profondi e validi, ma la loro
copertura satura: aumentare di oltre un ordine di grandezza il numero di programmi
validi raggiunge solo marginalmente più percorsi del verifier, perché il generatore
collassa su una modalità ristretta di programmi simili. Questo collasso ha origine
nella fase supervisionata; il ciclo di rinforzo, pur apprendendo, è stato troppo
breve per superarlo, lasciando aperto se un RL guidato dalla copertura possa
riuscirci. I contributi sono il sistema end-to-end, questo risultato negativo
caratterizzato con il suo meccanismo, e la correzione del reward, forniti come
pipeline open-source riproducibile.

\bigskip
\noindent\textbf{Parole chiave:} eBPF, fuzzing, modelli linguistici di grandi dimensioni,
apprendimento per rinforzo, copertura del codice kernel, KCOV, GRPO.

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

eBPF (extended Berkeley Packet Filter) has become a cornerstone of modern Linux
systems, enabling safe, sandboxed execution of user-supplied programs inside the
kernel for networking, observability, and security applications.
The eBPF verifier~--- the kernel component responsible for guaranteeing program
safety~--- is therefore a high-value target: logical flaws in the verifier can
allow unprivileged code to escape the sandbox and compromise the host system.

This thesis investigates whether a fine-tuned large language model (LLM) can fuzz
the Linux eBPF verifier --- a direction for which we find no prior published work.
From approximately 2 million eBPF programs collected at the kernel FFI boundary
using a modified version of the Buzzer fuzzer, we curate a balanced dataset of
27,000 samples across verifier error classes and fine-tune Qwen2.5-Coder-1.5B via
QLoRA. We then apply GRPO reinforcement learning with a reward derived from live
kernel code coverage (KCOV), using a validity-gated soft-floor reward that keeps
the within-group reward variance non-zero --- fixing a gradient-starvation
collapse that halts a naive design --- while still rewarding only valid programs.

Our central finding is that \emph{diversity, not validity, is the wall}.
Fine-tuning makes the model generate deep, valid programs, but their coverage
saturates: raising the number of valid programs by more than an order of magnitude
reaches only marginally more verifier paths, because the generator collapses onto a
narrow mode of similar programs. This collapse originates at the supervised stage;
the reinforcement-learning loop, though it learns, was too short to overcome it,
leaving open whether coverage-rewarded RL can. The contributions are the end-to-end
system, this characterized negative result with its identified mechanism, and the
reward fix --- delivered as a reproducible open-source pipeline.

\bigskip
\noindent\textbf{Keywords:} eBPF, fuzzing, large language models, reinforcement learning,
kernel coverage, KCOV, GRPO.
