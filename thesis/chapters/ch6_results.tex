\subsection{Plateau Diagnosis}
\label{sec:plateau-results}

\TODO{%
  Evidence from \texttt{results/grpo\_completions.log}:
  reward distribution collapses to a single value (0.1) for all rejected
  programs from step $\approx$1\,300 onward.
  \texttt{reward\_std} computed per batch drops to 0.

  GRPO gradient: $A_i = (r_i - \bar{r}) / \sigma_r$.
  When $\sigma_r = 0$: no gradient, no parameter update.
  Run continues consuming compute but the model does not change.

  Root cause confirmed by code inspection: \texttt{kcov\_validator}
  returned \texttt{pcs:[]} for REJECTED programs (Section~\ref{sec:rl-plateau}).
  All rejected programs were therefore indistinguishable from one another
  in GRPO's grouping.

  Literature grounding: the $\sigma_r = 0$ collapse is the gradient starvation
  failure mode analysed in~\cite{grpo-starvation}.

  Hypothesis (not provable from run~1 data due to simultaneous confounds):
  the \texttt{Status: VALID} prompt may have biased the model toward generating
  mostly valid programs during RL inference, reducing within-group diversity.
  The KCOV bug and the prompt bias coexisted in run~1; they cannot be disentangled
  without run~2 using a neutral prompt.
}
