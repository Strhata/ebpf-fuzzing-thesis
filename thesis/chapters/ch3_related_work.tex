\chapter{Related Work}
\label{ch:related-work}

This chapter surveys the prior work most relevant to this thesis across three
clusters.
eBPF-specific fuzzers define the target domain and establish the state of the art
for automated verifier testing.
LLM-based fuzzing systems demonstrate the viability of language-model-guided input
generation for complex software.
Reinforcement learning for code generation provides the algorithmic foundations
for the reward-signal design.
No prior work combines all three strands for the BPF verifier with live kernel
coverage feedback as the RL reward signal.

% --------------------------------------------------------------------------
\section{eBPF-Specific Fuzzers}
\label{sec:rw-ebpf}
% --------------------------------------------------------------------------

\textbf{Buzzer}~\cite{buzzer} is Google's open-source eBPF fuzzer, written in Go.
It implements two generation strategies: \texttt{pointer\_arithmetic}, which
produces programs that exercise pointer arithmetic rules, and
\texttt{coverage\_based}, which collects KCOV program-counter metrics from the
kernel and exposes them via an internal HTTP server.
A key finding of this thesis --- discovered during data collection and described
in Chapter~\ref{ch:methodology} --- is that the \texttt{coverage\_based} strategy
does \emph{not} use coverage to drive mutation: programs are generated by the same
hard-coded Go strategy regardless of which kernel paths they have already covered,
and KCOV is used solely for display purposes.
Buzzer is therefore not coverage-guided in the AFL sense; there is no feedback
loop from coverage observations back to the generation engine.
In this project, a modified buzzer instance serves as the data collection vehicle:
the \texttt{BPF\_PROG\_LOAD} boundary is instrumented to dump
(bytecode\_hex, verifier\_log) pairs to JSONL, producing the SFT training corpus.

\textbf{BRF}~\cite{brf} (FSE 2024) takes a type-aware, constraint-based approach
to eBPF program generation.
Rather than random mutation, BRF uses a generator that enforces the BPF type
system during construction, producing programs that are well-typed by design.
BRF's primary target is \emph{runtime} correctness: it searches for programs
that the verifier accepts but that exhibit incorrect semantics or undefined
behaviour at execution time.
This differs from the objective of this thesis in two respects.
First, the target layer differs: BRF tests the runtime behaviour of accepted
programs, while this work targets the verifier itself, seeking to exercise its
internal analysis logic.
Second, the generation mechanism differs: BRF's constraint solver encodes BPF
rules as logical constraints, while this work uses an LLM trained on real
program--verifier-log pairs to learn those rules implicitly from data.

\textbf{BpfChecker}~\cite{bpfchecker} (CCS 2024) uses differential fuzzing
across multiple eBPF runtime implementations to reveal implementation flaws.
Rather than targeting a single verifier, it cross-checks the behaviour of
different eBPF runtimes against each other to identify inconsistencies and bugs.
This differs from this thesis in two respects: BpfChecker targets
cross-runtime divergence rather than the internal analysis paths of a single
verifier, and it operates at the runtime-correctness level rather than using
coverage depth as an exploration signal.

\textbf{State Embedding}~\cite{state-embedding} (OSDI 2024) proposes learning
representations of abstract verifier states to improve the efficiency or accuracy
of verifier-related program analysis.
This internal-state approach is structurally distinct from the external black-box
generation approach of this thesis; the two directions are in principle
complementary, since richer state representations could inform reward signal
design in future extensions of this work.

\textbf{Veritas}~\cite{veritas} (SOSP 2025) addresses the correctness of the
eBPF verifier through formal or systematic analysis, aiming to prove or check
verifier properties rather than to discover unexplored paths through empirical
generation.
Its correctness-centred goal is orthogonal to the coverage-exploration goal of
this thesis; the two are complementary in that increased coverage may surface
precisely the edge cases that formal analysis must then characterise.

\section{LLM-Based Fuzzing}
\label{sec:rw-llm-fuzzing}
% --------------------------------------------------------------------------

\textbf{CovRL}~\cite{covrl} (ISSTA 2024) is the closest prior work to this thesis.
CovRL applies LLM-based mutation operators to JavaScript engine fuzzing, using
branch coverage as a reward signal to guide the mutation policy toward unexplored
engine code paths.
The paradigm is structurally identical to what this thesis implements: a language
model generates program candidates, a coverage oracle evaluates each candidate,
and a policy-gradient update trains the model to generate candidates that explore
new paths.
The differences lie in the target and instrumentation stack.
CovRL targets JavaScript engines, operating on source-level text and measuring
branch coverage via standard user-space tooling.
This work targets the Linux BPF verifier, a kernel subsystem, which requires live
kernel interaction via the \texttt{BPF\_PROG\_LOAD} system call, KCOV
instrumentation inside a dedicated virtual machine, and a purpose-built BPF
encoder to bridge LLM text output to the raw bytecode format the kernel expects.
CovRL demonstrates that the LLM + coverage-RL paradigm is viable for
language-runtime fuzzing; this work applies the same paradigm to a kernel
subsystem target, adding the challenges of live kernel instrumentation and
bytecode-level program representation.

\textbf{Fuzz4All}~\cite{fuzz4all} (ICSE 2024) introduces a universal LLM-based
fuzzer built on an autoprompting loop: an LLM is used both to distil the
specification of the target language into a condensed prompt and to continuously
regenerate diverse inputs from that prompt.
Fuzz4All targets compilers and language runtimes (C, C++, Python, SMT-LIB) and
focuses on generating syntactically and semantically valid programs to maximise
input diversity.
Unlike this work, Fuzz4All does not incorporate a coverage-driven RL loop: input
diversity is maintained through prompt variation rather than gradient-based
policy updates, and the system does not target kernel-level interfaces.

\textbf{KernelGPT}~\cite{kernelgpt} (ASPLOS 2025) uses LLMs to automatically
infer syscall interface specifications in the syzlang format consumed by syzkaller.
By reading kernel source code, KernelGPT generates descriptions of syscall
argument types, valid value ranges, and inter-argument dependencies that
syzkaller would otherwise require manual specification to encode.
KernelGPT operates at the specification level: it improves the grammar fed to
syzkaller rather than directly generating or evaluating programs.
This work differs in that the LLM is the generator: it produces BPF assembly text
directly, without an intermediate specification layer, and is trained end-to-end
on coverage feedback from the kernel.

\section{Reinforcement Learning for Code Generation}
\label{sec:rw-rl-code}
% --------------------------------------------------------------------------

\textbf{CodeRL}~\cite{coderl} (NeurIPS 2022) establishes the paradigm of using
program execution feedback as an RL reward for code-generating LLMs.
The CodeRL framework trains an actor (a code-generating model) alongside a critic
that predicts test-pass probability from the generated code, providing a dense
reward signal to improve functional correctness on competitive programming
problems.
Execution feedback --- whether generated code passes or fails unit tests ---
replaces the need for labeled correct solutions.
CodeRL targets functional correctness on algorithmic problems; its reward signal
is ultimately binary (pass/fail).
This work targets kernel verifier path coverage rather than functional
correctness, using the number of new kernel PCs reached as a continuous reward
that provides gradient signal beyond the acceptance boundary.

\textbf{GRPO gradient starvation}~\cite{grpo-starvation} formally analyses the
failure mode that derails RL run~1 of this thesis.
The paper establishes that when all $G$ completions in a GRPO group receive
identical rewards, the within-group standard deviation $\sigma_r$ collapses to
zero, the normalised advantages all vanish, and the policy gradient is
identically zero.
As a mitigation, the paper proposes replacing the standard within-group
normalisation with a fixed-reference advantage $A = 2r - 1$ for binary rewards,
which preserves a non-zero gradient even when group reward variance is zero.
This diagnosis and the proposed mitigation directly inform the reward redesign
described in Chapter~\ref{ch:methodology}.

\textbf{NGRPO}~\cite{ngrpo} (arXiv:2509.18851) proposes improvements to GRPO's
reward normalisation to stabilise training under skewed or multi-modal reward
distributions, addressing cases where the standard within-group variance estimate
is unreliable due to outlier rewards or small group size.
The normalisation strategies introduced by NGRPO offer a complementary algebraic
approach to the reward-stability goal pursued by the depth-based verdict-blind
reward proposed in this thesis: where NGRPO modifies the normalisation formula,
this work modifies the reward function itself to guarantee non-trivial within-group
variance by construction.
